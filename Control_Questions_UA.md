# Контрольні запитання — лабораторна робота 3.5

**1. Що таке модульне тестування?**  
Модульне (unit) тестування — це перевірка найменших логічно відокремлених частин програми, наприклад окремих методів або класів, незалежно від решти системи. Його мета — переконатися, що кожен компонент працює відповідно до вимог.

**2. Як використовуються модульні тести?**  
Їх запускають під час розробки та після змін у коді. Тести автоматично передають компоненту вхідні дані, виконують метод і порівнюють фактичний результат з очікуваним. Також їх запускають у процесі інтеграції та перед випуском програми.

**3. Назвіть вимоги до юніт-тестів.**  
Тести мають бути незалежними, повторюваними, швидкими, зрозумілими, ізольованими від зовнішніх ресурсів, перевіряти одну конкретну поведінку та мати однозначний результат. Вони не повинні залежати від порядку запуску.

**4. Наведіть переваги використання юніт-тестів у розробці ПЗ.**  
Вони рано виявляють помилки, спрощують рефакторинг, документують очікувану поведінку коду, зменшують ризик регресій, полегшують пошук причин помилок і підвищують впевненість у змінах.

**5. Що таке рефакторинг?**  
Рефакторинг — це покращення внутрішньої структури програмного коду без зміни його зовнішньої поведінки. Наприклад, винесення повторюваного коду в метод, перейменування змінних або поділ великого класу на менші.

**6. Які метрики та засоби використовуються для оцінювання ефективності застосування юніт-тестів у проекті?**  
Використовують покриття коду рядками, гілками та методами; кількість і частку успішних тестів; час виконання; кількість знайдених дефектів і частоту регресій. Засоби: Coverlet, Visual Studio Code Coverage, dotCover, OpenCover, ReportGenerator, а для запуску тестів — MSTest, NUnit або xUnit. Високе покриття саме по собі не гарантує якісних тестів.

**7. Що таке TDD? Назвіть переваги застосування TDD.**  
TDD (Test-Driven Development) — розробка через тестування: спочатку пишуть тест, який не проходить, потім мінімальний код для його проходження, після чого рефакторять рішення. Переваги: чіткіші вимоги, менше зайвого коду, краща тестованість і швидке виявлення помилок.

**8. Що таке принцип «Triple A»? Поясніть сутність його використання.**  
Triple A — структура тесту з трьох частин: Arrange (підготувати об'єкти та дані), Act (виконати дію, яку перевіряють), Assert (перевірити результат). Така структура робить тест зрозумілим і полегшує діагностику помилок.

**9. Як використовуються в юніт-тестах класи Assert?**  
Assert містить методи для перевірки очікуваного результату: `Equal`, `True`, `False`, `Null`, `NotNull`, `Empty`, `Single`, `Throws` тощо. Якщо умова не виконується, тест позначається як невдалий. У xUnit ці методи доступні через клас `Assert`.

**10. Як допомагає DI при написанні модульних тестів?**  
DI (Dependency Injection) — впровадження залежностей ззовні, а не створення їх усередині класу. Завдяки інтерфейсам у тест можна передати Stub або Mock замість реального файлового сховища чи бази даних. Це ізолює бізнес-логіку та робить тести швидкими й передбачуваними.

**11. Для чого потрібні модульні тести? Поясніть принцип FIRST.**  
Модульні тести перевіряють правильність окремих компонентів і допомагають швидко знаходити регресії. FIRST означає: Fast — швидкі; Independent — незалежні; Repeatable — повторювані; Self-validating — самостійно визначають успіх або невдачу; Timely — написані вчасно, бажано до або разом із кодом.

**12. Як правильно написати модульний тест?**  
Визначити одну поведінку для перевірки, підготувати мінімальні тестові дані, виконати метод, перевірити результат через Assert. Тест має бути ізольованим, мати описову назву, не залежати від мережі, реальної бази даних або порядку запуску. Бажано перевіряти також граничні та помилкові випадки.

**13. Чим модульні тести відрізняються від інтеграційних тестів?**  
Модульні тести перевіряють окремий компонент із ізольованими залежностями, тому зазвичай швидкі. Інтеграційні тести перевіряють взаємодію кількох компонентів або систем, наприклад бізнес-логіки з базою даних чи файловим сховищем; вони повільніші та потребують більше налаштувань.

**14. Що таке Mock та Stub? З якою ціллю вони використовуються в юніт-тестах?**  
Stub (заглушка) повертає заздалегідь підготовлені дані, щоб ізолювати компонент від реальної залежності. Mock (імітація) додатково дозволяє перевіряти взаємодії: чи був викликаний певний метод, скільки разів і з якими параметрами. Обидва засоби допомагають тестувати компонент незалежно від зовнішніх сервісів.
